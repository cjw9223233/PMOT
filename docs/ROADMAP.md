## 維護原則與責任

| 角色 | 責任 |
| --- | --- |
| PM／專案負責人 | 定義報告用途、優先順序、驗收條件與資料品質門檻。 |
| 維護者 | 檢查排程、判讀公告、處理事故、審查及合併 PR。 |
| 開發者 | 修改來源與測試、更新文件、提供可重現的驗證證據。 |
| GitHub Actions | 依既有程式自動檢查、保存與部署；不代替人工確認模糊公告。 |

由維護者定期檢查來源失敗、排程延遲與文件可用性，並在每次新增來源／調整排程／事故修復時更新本文件。
